# Tracing with Langfuse

**Goal:** every buyer message produces one Langfuse trace, with one observation per model call and per tool call,
tagged with provider, model and prompt version, with tokens, cost, latency and outcome on each turn. All messages
of a lead are grouped
as one Langfuse **session**. Tracing works in the app, in `npm run agent:try` and (Phase 4) in evals, and is off
when no Langfuse keys are set.

## What a trace looks like

```
session = leadId  (the whole conversation)
└─ trace "agent-turn"  (one buyer message)        tags: claude, claude-haiku-5-5, prompt-v1
   │  input: buyer message · output: reply · metadata: outcome, steps, cost, guard events
   │  (level WARNING / ERROR when the turn did not end as "replied")
   ├─ generation "llm-call 1"   model, messages in, text + tool calls out, stop reason,
   │                            usage (input, output, cache read, cache write), cost in USD, latency
   ├─ tool "update_lead"        input arguments, result (WARNING when ok: false)
   ├─ tool "search_listings"    …
   ├─ guardrail "price-guard"   amounts, retried / replaced   (only when it fires)
   └─ generation "llm-call 2"   …
```

**Change from the first design:** the memory/plan said "one trace per conversation". Langfuse's normal pattern is
one trace per request, grouped by `sessionId`. A conversation can last days; one trace per message keeps traces
small and comparable, and the Sessions view still shows the whole conversation.

## Design

- **An observer interface, not Langfuse calls in the loop.** `src/agent/observer.ts` defines `TurnObserver`:
  `turn(info, work)` wraps a turn; inside, the trace has `modelCall(...)` and `toolCall(...)` (each returns a
  handle to end it), `guard(...)` and `finish(...)`. The loop and `chat.ts` call it; the default is a no-op. Tests use a recording observer.
- **Langfuse only in one folder.** `src/agent/tracing/langfuse.ts` implements `TurnObserver` with
  `@langfuse/tracing`. ESLint blocks `@langfuse/*` and `@opentelemetry/*` everywhere else (same rule as provider
  SDKs).
- **Setup:** `src/agent/tracing/setup.ts` registers OpenTelemetry with the `LangfuseSpanProcessor` once, only when
  `LANGFUSE_PUBLIC_KEY` and `LANGFUSE_SECRET_KEY` are set (Zod-validated config). Next.js calls it from
  `src/instrumentation.ts`; scripts call it and **flush before exit** (otherwise the last spans are lost).
- **Tracing never breaks a chat.** Observer errors are caught and logged once; export runs in the background.
- **Cost is computed in our code**, not guessed by Langfuse: `src/agent/llm/pricing.ts` (USD per million tokens,
  with the date and source of the prices): Claude Haiku 5.5 $0.10 / $0.50, Sonnet 5.5 $2 / $10, Opus 5.5 $4 / $20,
  cache reads 0.1× (Haiku) or 0.05× (Sonnet, Opus), cache writes 1.25× of the input price; local models $0. The same number goes to Langfuse
  (`costDetails`), to the saved turn meta, and to the agent view.
  - Needs one small model-layer change: `LlmUsage` gets `cacheWriteInputTokens` (Claude's
    `cache_creation_input_tokens`), so cache writes are priced correctly. Contract test updated.
- **What is sent to Langfuse:** the buyer message, the reply, the messages sent to the model, tool inputs and
  results. No API keys, no system prompt text per call (the prompt **version** is a tag instead; the prompt itself
  is in the repo). The data is fictional demo data. A masking hook exists in `LangfuseSpanProcessor` if this ever
  handles real buyers; not added now.
- **Agent view:** the model-turns table gets a cost column and a total per lead; each turn stores its Langfuse
  trace id.

## Tests

- Loop emits: turn start → model call → tool calls → … → turn end with outcome; one model-call event per retry; the
  price guard emits a guard event; a provider error ends the model call with the error.
- An observer that throws does not change the reply or the saved messages.
- Pricing: Haiku with cache reads and writes; unknown model → cost `null` (shown as "—"), never a made-up price.
- Langfuse mapping (in-memory exporter): one root span per turn with session id and tags; child generations with
  model, usage and cost; tool observations with level WARNING when `ok` is false (a failed tool is not always a
  bug: "slot taken").
- No keys → no exporter registered, no errors.

## Result

- `npm run check` green: **232 tests** (204 → 232 over Phase 3, including the frozen-prompt change);
  `npm run build` green. ADR 0005 (tracing) and ADR 0006 (frozen system prompt).
- **Real runs, Claude Haiku 5.5, traced to Langfuse Cloud (EU):**
  - `npm run agent:try` (5 messages, 2 conversations): every turn `replied`; **$0.00330** in our logs. Langfuse
    sessions: qualify-and-book (4 traces) **$0.003092** + ask-for-a-person (1 trace) **$0.000205** = $0.003297.
  - A 3-call turn ("Can I see it on Saturday?"): llm-call-1 $0.000221 + llm-call-2 $0.000396 + llm-call-3
    $0.000404 = **$0.00102**, the same as saved in the turn meta. 18k tokens, 2.75 s.
  - **Inside Next.js** (`npm run dev`, `POST /api/chat`): `[tracing] on`, trace id saved with the turn; the trace
    is a clean root (no Next.js spans): llm-call-1 $0.000573 + 2 tools + llm-call-2 $0.000192 = $0.000765 (our
    meta: $0.0007657, including a 3,380-token cache write on a fresh process).
- **Found by looking at real traces:**
  1. **Double counting:** the Anthropic SDK emits its own `anthropic.messages.create` spans and Langfuse exported
     both (first run: $0.00486 in Langfuse vs $0.00243 ours). Fixed with `shouldExportSpan: isLangfuseSpan` + test.
  2. **Claude 400 "system prompt differs"** on the second call of every turn: the dynamic part of the system
     prompt changed after `update_lead`. Fixed (ADR 0006): frozen system prompt, a `context` message once per
     turn, and a regression test that every call keeps the same system prompt and only extends the last request.
- **Changes from the plan:** observer API names (above); failed tools are WARNING, not ERROR; no "outcome" tag
  (outcome is in metadata and level); the `isLangfuseSpan` filter; OpenTelemetry warnings are logged (export
  failures were silent); a new `context` message role (ADR 0006); a per-model cache-read rate in the price table.
- **Not done:** the Gemma trace run. LM Studio was not running on 2026-11-17; the local path is covered by unit
  tests. Run `npm run agent:try` with `LLM_PROVIDER=local` when LM Studio is up.

**Architecture review: needs changes → fixed.** Blocking:

1. Cache reads for Sonnet / Opus 5.5 were priced at 0.1× (they are 0.05×) → per-model rate + test.
2. `observeTurn` could run a turn twice if an observer failed while the turn was still running → it now waits for
   the run that already started + test.
3. ADR 0006 said old Claude conversations still replay → corrected: they cannot continue (new chat or reseed).
4. Plan and docs out of date → updated (architecture request flow and context rules, README tracing,
   `prompts/types.ts` comments).

Suggestions applied: OpenTelemetry warning logger; a guard so a misplaced context can never cause a permanent 400;
tests for context after tool results (Claude and local); notes in ADR 0006 on Sonnet's fallback model, trace size
and prompt-v1 comparability. Noted, not done: caching the message history (a second cache breakpoint), counting a
declined fallback attempt's tokens, and ESLint not seeing dynamic `import()`.
