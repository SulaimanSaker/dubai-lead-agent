# Prompt v2: answer when the buyer names a price

**Goal:** fix the agent's one real weakness from the Phase 4 baseline, measured the same way. When the buyer names a
price ("Is that one really only 80k?", "Would the owner accept 1 million?"), the agent should answer with the real
price or hand off, without repeating the buyer's number. Today the price guard blocks the draft and the buyer gets
"Which property would you like the details of?".

## What the baseline shows (Claude Haiku 5.5, 31 cases × 3)

| Case                         | Passed | What happens                                                                                                                           |
| ---------------------------- | ------ | -------------------------------------------------------------------------------------------------------------------------------------- |
| `buyer-states-a-wrong-price` | 0/3    | The draft corrects the buyer but repeats "80k". The guard rejects it, the retry repeats it again, and the turn ends with the fallback. |
| `offers-a-lower-price`       | 1/3    | The draft says "your offer of AED 1,000,000". After the correction, 1 of 3 retries says "your offer" without the number and passes.    |

The guard is right to block these: it can't tell "it's not 80k" from "yes, it's 80k", and confirming a number
only the buyer said is exactly what it must prevent. What's missing is **telling the model how to talk about the
buyer's number**. The current correction note only says "use prices exactly as the tools returned them".

## Changes

### 1. Judge v3 first, then re-grade the baseline

The before/after comparison has to use the same judge, so fix the judge before running v2:

- Stop clipping tool results at 1,200 characters (a few slot lists are up to ~2,000). New limit: 6,000.
- Reword "facts stated here are true" to "rules and general facts here count as grounded; example values in the
  instructions (like "AED 115,000") are not facts about any listing".
- `JUDGE_VERSION = "v3"`, then `npm run evals:rejudge` on every saved run and re-score calibration.

### 2. Run a chosen prompt version

- `npm run evals -- --prompt v2 --variant v1` (default: the current prompt, in the folder that already holds it).
  _Changed while building:_ the vendored report builder reads only `baseline` and `v<N>` folders, so the v2 run
  lives in `evals/runs/claude-haiku-5-5/v1/` with a `change.md`; `evals/lib/variants.ts` picks the folder.
- `handleBuyerMessage` deps get an optional `prompt` (the loop already accepts one).
- Every row saves `prompt_version`. The runner refuses to add rows to a folder that holds another prompt
  version, so rows can't be mixed silently. The existing rows get `prompt_version: "v1"` (checked against
  their trace headers).
- `compare` shows one row per model **and variant**.

### 3. Prompt v2 (`change-prompt` skill)

`src/agent/prompts/v2.ts`: a copy of v1 with one new rule and one example. Nothing else changes:

> - **When the buyer names an amount** (an offer, or a price they think something costs), don't repeat their
>   number. Say "your offer" or "that price", and give only the price a tool returned. Example: buyer: "Is it
>   really only 80k?" → "It's AED 115,000 per year."

### 4. A clearer correction note, per prompt version

The note sent when the guard rejects a draft becomes part of the prompt version
(`PromptVersion.priceCorrection`). v1 keeps today's text, so the baseline stays reproducible. v2 adds: "Amounts
the buyer said count too: don't repeat them, say 'your offer' or 'that price' instead." The guard itself
**doesn't change**.

### 5. Measure

1. Null agent on all 31 cases (it ran on only 9): the agent costs nothing, the judge about $0.07.
2. Haiku 5.5 with prompt v2, 31 × 3: about $0.50, 3 minutes.
3. Optional: Gemma 3 4B with prompt v2, 31 × 1. The agent is free and takes about 16 minutes; the judge costs
   about $0.14. v2 isn't expected to fix Gemma's tool misuse, but the run shows whether the rule hurts it.

**v2 replaces v1 in the app (`CURRENT_PROMPT`) only if all of these hold:**

- The two target cases together pass at least 5 of their 6 runs (3 reps each).
- No other check drops by more than 3 points.
- The headline pass is at least as high as v1's.

Otherwise v1 stays, and we write down why.

## Tests

- Prompt v2: stable text, the new rule is present, and v1 is unchanged.
- The loop uses the prompt's own correction note (v1 text for v1, v2 text for v2).
- `handleBuyerMessage` runs with a given prompt and records its version.
- The runner refuses a folder whose rows have a different prompt version, and saves `prompt_version`.
- Judge v3: long tool results are no longer clipped at 1,200, and the new wording is in place.

## Alternatives considered

- **Let the guard accept amounts the buyer said:** rejected. "Yes, it's 80k" would pass, which is the hole the
  Phase 2 review closed.
- **Try to detect "correcting" versus "confirming" in code:** rejected. It's guesswork with regexes, in two
  languages.
- **A smarter fallback reply** (no "which property?" when a listing is clear): helps only after the model has
  already failed twice. Left for later; the fallback rate is measured.

## Cost and time

About $1.10–1.25 for judge v3's re-grade, the null run, the Haiku v2 run and the optional Gemma run. About 1–1.5
hours of work.

**Status:** DONE (2026-11-21). v2 won against v1; v3 (v2 with a non-fixture, language-neutral example) is now the app's prompt (`CURRENT_PROMPT`). Approved 2026-11-21 with: pause before paid runs, Gemma v2 run skipped.

**Architecture review (2026-11-21): one honest caveat.** The example in v2's new rule ("Is it really only 80k?" →
"It's AED 115,000 per year.") is almost word for word the target case `buyer-states-a-wrong-price`, answer
included (L02 is AED 115,000). So that case's 0/3 → 3/3 is partly teaching to the test. `offers-a-lower-price`
(1/3 → 3/3) is not in the prompt and suggests the rule generalises, but that is one case. To check, held-out cases
with other listings, other numbers and Arabic are proposed (they need the human's sign-off, like all cases).
Also from the review:

- Judge calibration was done on prompt v1 replies only (`evals/calibrate.ts` reads `baseline`); the v2 rows are
  graded by the same judge v3, but nobody labelled v2 replies.
- Fixed: the runner now also refuses a turn whose saved prompt version differs from the one asked for
  (`prompt_mismatch`, like `model_mismatch`); `variants.ts` refuses to guess when two folders hold the same
  prompt version; a `v<N>` folder needs its `change.md` first; `--prompt` ignores inherited keys; `compare` only
  reads `baseline` / `v<N>` folders. New tests lock v1's dynamic part and run the price guard under prompt v1.

**Held-out cases (approved and added 2026-11-21, 3 reps each, judge v3, $0.09):**

| Case                                                                           | Prompt v1                      | Prompt v2                |
| ------------------------------------------------------------------------------ | ------------------------------ | ------------------------ |
| `buyer-states-a-wrong-sale-price` (L17, AED 1,950,000; buyer says 1.2 million) | 1/3 (2 × price guard fallback) | **3/3**                  |
| `arabic-buyer-states-a-wrong-price` (L28, AED 110,000; buyer says 70 ألف)      | 3/3                            | 3/3 (1 reply in English) |

- The English held-out case behaves like the original target: v1 is blocked by the guard, v2 answers "the price
  is AED 1,950,000". So the rule generalises beyond its own example.
- **New finding: the price guard can't read Arabic amounts.** `findMoneyAmounts("نعم، السعر 70 ألف درهم سنويًا")`
  returns nothing: the pattern knows "k" and "thousand" but not "ألف" / "مليون". v1 "passed" the Arabic case only
  because the guard never saw "70 ألفًا" in its replies. A reply confirming a made-up price in Arabic would pass
  too. This hole dates from Phase 2, not from v2.
- v2 rep 1 answered the Arabic buyer in English on turn 2. The `language` check caught it (0), but language is
  reported apart from the headline `pass` (Phase 4 design).

2. **Language now counts in the headline `pass`.** The saved rows were recomputed without model calls; 1 row

**New finding: prompt v2 makes Haiku answer an Arabic price question in English.** On
